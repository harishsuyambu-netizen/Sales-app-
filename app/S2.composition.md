## Composition and regions

- **S2.R1 [R9, A1] — Persistent navigation (fixed chrome).** Use the shared CRM navigation, with Leads selected. Keep all destinations reachable at narrow widths through the horizontally scrolling row.
- **S2.R2 [R2, R3, A3] — Page heading and primary action.** Show `Leads` and `Qualify new enquiries and turn them into deals`. Place `Add lead` at the right of the heading on wide screens; on narrow screens place it directly beneath the subtitle, before search/results. Activating it reveals the entry region and moves focus to Name.
- **S2.R3 [R3, A3, A4] — Lead entry region (conditional, before list).** While open, place the form immediately after the heading and before filters/results so validation and Save/Cancel remain near the initiating action. On wide screens arrange Name and Company in the first pair and Source and Expected value in the second pair; put inline validation and Save lead/Cancel below. At narrow widths stack all fields in Name, Company, Source, Expected value order and keep actions visible after the fields. Use persistent labels; retain source placeholders as examples: `Rahul Deshmukh`, `Company name`, and `450000`. Source choices are Website, Referral, LinkedIn, Trade show, Cold call. Expected value accepts zero or more. Do not represent a source selection or numeric value using color alone.
- **S2.R4 [R2, A2] — Filter and search row.** Put status chips in exact order All, New, Contacted, Qualified, Converted, Lost, then the case-insensitive name/company search. At wide widths, chips and search share one row, with search aligned to the far side; at narrow widths chips wrap in order and search uses the full next row. Retain the current search/filter context until a successful add resets the filter to All; clearing search reveals the current status subset.
- **S2.R5 [R2, R4, A5] — Lead results table.** Under the filter row, show the main bordered white list card. Keep table headings aligned with rows and columns in this order: Lead (initials, name, company), Source, Score (bar plus numeric score), Value, Status, available action. Preserve name/company as the primary identity grouping. Apply the specified text-and-pill status distinctions: New bordered white, Contacted tinted blue, Qualified blue, Converted green, Lost muted panel. For eligible statuses, place `Convert to deal` within that lead’s row; do not offer it for Converted or Lost. Conversion updates the selected lead and creates the same-company Qualified deal with its value and owner, then shows `Converted to a deal in Qualified` at the shared toast location.
- **S2.R6 [R2–R4, A3–A5] — Validation, empty state, and action feedback.** Keep validation directly below the form fields: missing name/company displays exact `Enter a name and company` and creates nothing; make the first missing field discoverable and focus it. If combined filter/search yields no rows, replace the row area with `No leads match.` Do not hide the filter or search. On a valid save create New status, score 60, selected source, entered value (or zero), owner AK; clear the form, close it, reset filter to All, refresh affected views, and show `Lead added`. Cancel closes and clears the error without creating a row; return focus to `Add lead`. Success feedback uses the shared transient bottom-center region.

## Spatial behavior and states

At 1366 × 768, keep heading/action, one compact form when open, and the filter/search row above the results. The list is the dominant region and takes remaining page width. The page content owns vertical scrolling, bounded by fixed navigation/chrome; the table does not own vertical scrolling. At 900 px and above, the full lead table is visible without horizontal scrolling when practical. On narrow screens, keep columns intact and localize horizontal scrolling to the table and its aligned headings; the identity column is first and visible initially, and all other fields/actions remain reachable by horizontal movement. No required field may be dropped to fit. Form fields stack; the results card follows the form and filters. At 320 × 720, vertical page scrolling reveals remaining table rows rather than compressing record text.

## Reading, focus, and accessibility

Order: selected navigation and other destinations; heading; Add lead; if open, Name, Company, Source, Expected value, validation, Save lead, Cancel; then status filters left-to-right, search, table headings, each row left-to-right and top-to-bottom, and row conversion action. Keep labels persistent and programmatically associated in implementation. Expose selected filter state and status as text. Provide numeric score in addition to the score bar; identify row action with its lead name so the target is unambiguous. Table headers remain associated with horizontally scrolled data. On invalid save announce the error and focus the first missing required field; on valid save or conversion announce the exact success message. On cancel return focus to the initiating Add lead action. `No leads match.` is announced as the result state.
